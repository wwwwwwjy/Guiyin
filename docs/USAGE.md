# 使用手册

适用于 0.9.21-r2。先完成根目录 README 中的挂载与账号配置。

## 1. 音乐总览

本地音乐数来自选定目录中的音频文件；来源歌曲数是平台关联记录；飞牛索引数是飞牛当前可见的逻辑曲目。三者统计口径不同，不能直接当作下载失败数量。下载活动和评论覆盖统计用于观察运行情况。

## 2. 平台账号与指定歌单

在“订阅与融合”选择平台并扫码。扫码成功后读取喜欢、创建与收藏的具体歌单；可以选择单独歌单或平台支持的榜单。登录成功只是建立账号连接，不代表所有歌单都已启用下载。

登录状态由各平台决定。若账号过期，重新扫码后再重试任务；来源列表未完整读取时保留上次完整结果，避免错误删除关系。

## 3. 配置融合与目录

1. 点击“读取账号歌单”，等待具体子歌单出现。
2. 点击“新建融合”，填写名称并浏览选择 `/music` 内的保存目录。
3. 仅勾选需要汇入的具体来源，保存后确认来源与目录。
4. 点击“开始同步”。停止同步后可以继续调整分类。

例：网易云“我的喜欢”+ QQ“我的喜欢” → 融合“我的喜欢” → `/music/我的喜欢`；网易云“下雨天听” → 独立融合 → `/music/下雨天听`。

同一歌曲可能属于多个文件夹，文件副本与各歌单关联需分别核对。不同版本不强行合并。取消勾选后暂停该来源，已有文件保留；需要删除文件时请自行在文件管理器核对处理。

飞牛音乐媒体库必须覆盖这些保存目录。文件下载完成后，归音等待飞牛入库再更新自己管理的“归音 · 名称”歌单，歌单封面选取来源顺序中的第一个可用歌曲封面。它不承诺零延迟，也不会接管无关的手动歌单。

## 4. 搜索、试听与下载

“探索音乐”勾选平台并输入歌名或歌手。先核对歌手、专辑和版本，再试听或下载。试听优先利用已有本地音频；平台只允许试听时标注片段。下载音质在“平台与设置”统一配置，优先音质不可用时尝试较低音质的完整音频。

## 5. 任务中心

- 按状态筛选，查看总条数与总页数。
- “全选本页”只选择当前页；“全选当前筛选结果”可选择跨页下载任务。
- “开始下载”可处理适用的失败、等待处理或暂停任务；“重试下载”按最新配置重新尝试。
- “暂停下载”暂停所选任务，“取消下载”终止所选任务，均不删除已下载文件。
- “清除所有下载任务”清理下载任务记录，不是删除曲库。
- 来源尝试明细可区分解析、网络、完整性及权限错误。已有活动任务时会跳过重复安排，避免并发写同一首。

## 6. 音源管理

内置源始终有对应项目文件；新增配置和 JS 文件持久化到数据卷，升级不应丢失。可以添加 HTTP 源、导入 JSON 或 LX JS，测试可用性、停用、导出、调整优先级。

按优先级从小到大尝试适用源。解析失败、传输失败或音频验证失败才继续下一个；一个源可下载部分歌并不意味着它适用于全部歌曲。保存优先级用于后续任务及重试。配置格式、平台映射和运行限制见 [源文档](../app/sources/README.md)。

不要向不信任的音源发送私人信息或导入来源不明的脚本。项目不会把平台账号 Cookie 直接附加到自定义音源请求。仓库不分发用户导入源及其密钥。

## 7. 评论聚合

“评论聚合”可以添加多个目录（包含子目录），新目录默认暂停。点击“继续”后扫描并采集，每个目录可独立暂停或重新扫描；进度持久化，重启后继续。重叠目录共享同一文件的采集进度。

目录卡片显示总量、完成、待采集、处理中、待重试。批次状态展示当前歌曲、新增评论、已用时间和估计剩余时间，网络与限流会影响估算。完成表示达到采集目标或当前来源没有更多评论。也可先试采少量歌曲验证连接，再决定范围。

“音乐台”新开增强页面，播放时展示对应歌曲的聚合评论。评论按网易云、QQ、酷狗来源保留作者、时间和可用的点赞信息。跨平台身份无法可靠匹配时可能没有该平台评论。

## 8. 歌词及封面目录补全

添加目录后点击继续，逐首检查资源，之后每 5 分钟检查新增文件。各目录独立暂停、继续和查看明细。已存在的歌词或封面不覆盖，只补全缺少项。

启用音源按优先级辅助匹配；歌词与封面可由不同源补齐。匹配检查歌名、歌手与时长，不会因为名字相似就强行写入。仅能提供音频的源自动跳过。

资源使用音频相同文件名放在相同目录，例如：

```text
我的喜欢/
├── 歌手 - 歌曲.mp3
├── 歌手 - 歌曲.lrc
└── 歌手 - 歌曲.jpg
```

封面实际也可能是 PNG 等格式；支持的音频文件会写入封面标签。目录已扫描而所有资源齐全时，显示“已有信息，已跳过 N 首”，进度满格表示本轮检查完成。部分项目未匹配时也会结束本轮处理，并明确保留“未完全匹配”数量，满格并非保证全部补全。

## 9. 歌曲信息修复

单独添加目录，默认暂停。点击继续后检查文件标签，之后每日检查；也可以立即检查。当前自动修复专辑与发行年份，匹配规则：

1. 歌名规范化后一致，完整歌手集合一致，时长差不超过 2 秒。
2. 至少两个启用的原生平台对待修复字段一致。
3. 其他匹配候选没有冲突；证据不足则不修改。
4. 只更新标签，不转码、不改文件名，写入前保存完整原文件。

“最近修改记录”展示修改前后值、证据平台及撤销入口。若文件后来被其他工具改动，撤销会拒绝覆盖；已经撤销的原文件不会立即被同样规则再次修复。备份占用与原音频相近，请预留数据卷空间。

不能保证上游元数据绝对正确。不要把“多个平台一致”理解为所有版本都无歧义；不可靠的歌名/歌手不会自动猜测修正。

## 10. 设置、维护与作者支持

设置页管理下载音质、音源、飞牛连接及程序支持信息。目录选择范围由 Docker 挂载决定。请保留第三方许可与署名。

设置最底部的“请作者喝一杯咖啡”按钮点击后显示作者支付宝和微信二维码，没有管理员上传替换入口。二维码是源码中固定资源，开源代码本身仍可被派生项目修改，不能理解为技术上无法更改。

维护时备份数据卷与配置；音乐文件另行备份。避免同时运行多个实例或多 worker 争用数据库及文件。排错见 [FAQ](FAQ.md)。
